# 测试用例智能生成系统产品汇报文档

> 维护要求：每次系统版本更新、功能迭代或能力下线后，必须同步更新本文件。

## 1. 产品概述

测试用例智能生成系统是一套面向测试设计与接口测试执行的 AI 平台。系统支持用户上传思维导图、流程图、界面截图、表格、文档和外部链接等多种材料，并结合用户输入的测试要求、业务背景和上下文信息，自动生成结构化测试用例，支持页面展示、Excel 导出、历史记录、报告汇总、缺陷跟踪和接口执行。

当前版本已经从单一的“AI 生成用例工具”演进为具备以下四类能力的综合平台：

1. AI 测试设计能力
2. 接口测试执行能力
3. 测试资源保存与历史查询能力
4. 报告汇总与失败项跟踪能力

## 2. 建设背景

在传统测试工作中，测试人员经常面临以下问题：

1. 需求材料来源分散，既有图片、流程图，也有 PRD、接口文档和表格，整理成本高。
2. 测试用例编写依赖人工分析，效率受个人经验影响较大。
3. 接口文档与实际测试执行之间存在断层，生成出来的用例不一定能直接落地执行。
4. 用例、执行结果和历史记录分散在多个工具中，难以统一保存、查询和复用。

本系统的目标就是把“输入材料整理、测试设计、接口执行、结果汇总、问题跟踪”串成一条统一链路。

## 3. 产品定位

当前产品可定位为：

**AI 测试设计与接口测试执行平台（初版）**

它不是只负责生成测试点的轻量助手，而是一套可完成“多源输入 -> AI 生成 -> 质量分析 -> 接口执行 -> 报告汇总 -> 缺陷跟踪 -> 历史查询”的测试工作平台。

## 4. 目标用户

### 4.1 测试工程师

- 希望快速基于 PRD、页面稿、流程图生成测试用例
- 希望将接口测试设计与执行统一在一个平台中完成
- 希望保存测试资源并减少重复劳动

### 4.2 测试负责人 / QA Lead

- 希望提升团队测试设计效率
- 希望评估测试覆盖情况和用例质量
- 希望形成可复盘、可追踪的测试输出

### 4.3 研发 / 产品协作人员

- 希望快速查看测试重点和覆盖范围
- 希望把接口契约快速转成可执行测试
- 希望利用 AI 降低前期测试设计沟通成本

## 5. 当前版本核心价值

### 5.1 多源输入统一处理

支持图片、表格、文档、文本和链接等多种输入来源，能够把分散材料统一纳入测试设计上下文。

### 5.2 自动生成结构化测试用例

系统可以根据输入材料自动生成标题、前置条件、测试步骤、预期结果、优先级和覆盖标签等结构化用例内容。

### 5.3 支持接口测试直接执行

生成结果不只停留在“文档层面”，而是支持对接口类用例进行请求发送、断言校验、变量提取、链路串联和并发执行。

### 5.4 支持覆盖率与质量评估

系统会从需求、接口、字段、异常、边界、权限等维度分析覆盖情况，并对用例的可执行性与可验证性进行评分。

### 5.5 支持结果导出、历史保存与执行闭环

测试结果支持自动导出为 Excel，同时可写入 MySQL，形成生成历史、执行历史、报告汇总和结果回查能力。

## 6. 核心功能模块

## 6.1 多源材料输入

当前支持的输入类型包括：

- 图片：思维导图、流程图、界面截图
- 表格：Excel、CSV、TSV
- 文档：Word、PDF、Markdown、TXT、JSON、YAML、HTML、日志类文本
- 链接：飞书文档、PRD、接口文档、普通网页
- 用户补充输入：测试要求、上下文背景、业务说明

该模块解决的是“测试设计前的材料收集与整理”问题。

## 6.2 AI 测试用例生成

系统可基于输入材料自动生成结构化测试用例，当前生成结果通常包括：

- 用例标题
- 前置条件
- 测试步骤
- 预期结果
- 优先级
- 覆盖标签
- 测试数据建议
- 部分接口类用例的执行配置

系统支持流式输出，前端可边生成边展示，提升可感知性和等待体验。

## 6.3 用例展示与工作台

前端当前已经形成统一工作台，支持：

- 工作台录入
- 用例卡片视图
- 用例表格视图
- 用例生成结果查看
- 报告中心查看
- 缺陷跟踪查看
- 历史记录查看
- 历史记录内下载 Excel

整体界面以科技风和集中工作台为主，便于连续操作。

当前右侧主内容区已经按测试流程顺序组织为：

1. 工作台
2. 用例生成
3. Swagger 导入
4. 接口执行
5. 报告中心
6. 缺陷跟踪
7. 历史记录

## 6.4 Swagger / OpenAPI 导入

系统支持导入 OpenAPI / Swagger 的 JSON 或 YAML 文档，自动生成接口测试用例。

当前重点覆盖的测试场景包括：

- 正向场景
- 缺参场景
- 非法参数场景
- 边界值场景
- 权限校验场景
- 幂等性相关场景

该能力适合“已有接口契约，想快速落测试”的团队。

## 6.5 接口测试执行

系统已具备基础到中等强度的接口执行能力，支持：

- 单接口执行
- 用例集顺序执行
- 并发执行
- 重复执行
- 失败中断
- 变量提取与接口串联

支持的方法包括：

- GET
- POST
- PUT
- PATCH
- DELETE
- HEAD
- OPTIONS

支持的请求体格式包括：

- raw
- json
- form
- multipart

## 6.6 报告中心

报告中心用于把接口执行结果从“单条执行记录”提升为“可汇总查看的测试报告”，当前支持：

- 汇总最近执行次数、通过数、失败数和通过率
- 展示最近接口运行记录
- 展示当前覆盖风险数量和概览提示
- 结合用例质量评分、执行状态形成阶段性测试视图

这个模块适合在一次测试执行后快速给出“本轮执行情况怎么样”的答案。

## 6.7 缺陷跟踪

缺陷跟踪模块用于对失败项进行持续管理，当前支持：

- 自动同步接口执行失败项
- 区分待处理、处理中、已解决三种状态
- 维护优先级、负责人和跟踪备注
- 为失败项提供建议动作，方便继续定位问题

这个模块让平台从“发现失败”走向“持续跟踪失败项”。

## 6.8 断言与数据库校验

当前支持的断言与校验能力包括：

- 状态码断言
- 响应内容断言
- Header 断言
- JSONPath 断言
- 正则断言
- 存在性断言
- 大小比较
- JSON Schema 校验
- 响应时间断言
- MySQL 只读 SELECT 校验

这部分能力使平台具备“从设计结果走向实际执行验证”的基础条件。

## 6.9 覆盖率与质量评分

系统当前会从以下维度分析覆盖情况：

- 需求
- 接口
- 字段
- 异常
- 权限
- 边界
- 数据一致性
- 性能
- 安全

同时会对生成用例进行质量评分，关注：

- 步骤可执行性
- 预期可验证性
- 测试数据充分性
- 覆盖标签完整性
- 自动化就绪度
- 重复度

## 6.10 失败分析与历史查询

在接口执行失败后，系统可对失败原因进行分类分析，例如：

- 环境问题
- 鉴权问题
- 参数问题
- 断言问题
- 契约变更
- 后端缺陷
- 数据一致性问题

如果启用 MySQL，系统还能保存：

- 生成会话
- 输入摘要
- 材料摘要
- 用例明细
- Excel 下载地址
- 接口执行历史
- 响应摘要
- 断言结果
- 变量提取结果
- 执行耗时

## 7. 用户使用流程

### 7.1 AI 生成主流程

1. 用户进入工作台
2. 上传图片、文档、表格或粘贴外部链接
3. 输入测试要求和上下文背景
4. 发起 AI 生成
5. 前端实时展示生成中的测试用例
6. 查看用例内容、覆盖率和质量评分
7. 下载 Excel
8. 保存历史记录

### 7.2 Swagger 导入流程

1. 用户进入 Swagger 导入模块
2. 粘贴文档内容或填写文档 URL
3. 系统解析接口契约
4. 自动生成接口测试用例
5. 展示覆盖率和生成结果
6. 支持导出和历史查询

### 7.3 接口执行流程

1. 用户进入接口执行模块
2. 手工填写接口配置或使用已生成用例
3. 配置断言、变量提取和数据库校验
4. 执行单接口或用例集
5. 查看执行结果与失败分析
6. 保存执行历史

### 7.4 报告与缺陷跟踪流程

1. 用户进入报告中心查看最近执行汇总
2. 按通过率、失败数和覆盖风险判断本轮测试结果
3. 将失败项同步到缺陷跟踪模块
4. 为失败项补充优先级、负责人和备注
5. 跟踪状态变化，直到问题关闭

## 11. 汇报结论

测试用例智能生成系统当前已经完成从“多源材料输入”到“AI 用例生成”再到“接口执行、报告汇总、缺陷跟踪与历史查询”的基础平台化建设，具备了初版智能测试平台的雏形。

它的价值不再局限于帮助测试人员编写几条测试用例，而是在逐步形成一套覆盖测试设计、执行验证、结果汇总和测试资源保存的统一工作平台。对于需要提升测试设计效率、提升接口测试落地能力和保存测试资源的团队来说，这套系统已经具备明确的试点和内部推广价值。
