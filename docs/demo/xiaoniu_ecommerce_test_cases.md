## 2. 用例设计原则

本轮用例不是只验证接口可达，而是围绕电商订单主链路设计：

- 登录鉴权：正确登录、错误登录、无 token、错误 token。
- 权限边界：普通用户不能执行管理员重置。
- 商品库存：商品列表、库存为 0、超库存数量。
- 购物车：加入、查询、删除、非法商品、非法数量。
- 订单流程：创建订单、订单详情、支付、取消。
- 状态流转：重复支付、已支付取消、已取消支付。
- 异常场景：不存在订单、空购物车下单、删除不存在商品。

## 4. 本轮发现的重点缺陷

根据 2026-06-24 的实际执行结果，以下用例未通过：

| 用例 | 期望 | 实际 | 判断 |
| --- | --- | --- | --- |
| XE-012 数量为 0 加入购物车 | 返回 400 | 返回 200，并加入 1 件商品 | 参数校验缺陷 |
| XE-015 库存为 0 商品加入购物车 | 返回 400 | 返回 200，并加入购物车 | 库存边界缺陷 |
| XE-023 重复支付已支付订单 | 返回 400 | 返回 200，仍提示 success | 状态流转缺陷 |
| XE-037 超库存数量加入购物车 | 返回 400 | 返回 200，可加入 99 件 | 库存数量校验缺陷 |
| XE-043 删除不存在购物车商品 | 返回 404 | 返回 200 | 异常处理策略不明确 |

其中前 4 项更像真实业务缺陷；最后 1 项也可能是接口采用“删除幂等成功”的设计，需要和产品或接口规范确认。
