# 小牛电商订单测试实战项目需求分析

## 1. 被测系统

小牛电商订单测试实战项目是一个面向软件测试练习的电商业务系统，前端入口为：

```text
http://www.ceshixiaoniu.com/ecommerce-practice-app.html
```

后端接口基础地址为：

```text
http://43.133.227.52/api
```

测试账号：

| 角色 | 账号 | 密码 | 用途 |
| --- | --- | --- | --- |
| 普通用户 | tester | 123456 | 登录、商品、购物车、订单、支付、取消 |
| 管理员 | admin | admin123 | 重置练习数据 |

## 2. 核心业务流程

普通用户的主流程是：

```text
登录 -> 查询商品 -> 加入购物车 -> 查询购物车 -> 创建订单 -> 查询订单 -> 支付订单 / 取消订单
```

管理员流程是：

```text
管理员登录 -> 重置练习数据 -> 普通用户重新执行主流程
```

## 3. 可测试问题

### 3.1 登录与鉴权

- 正确账号密码是否能登录成功。
- 错误密码、空账号、空密码是否被拒绝。
- 登录成功后是否返回 token。
- 无 token 或错误 token 访问业务接口是否返回 401。
- 普通用户是否不能执行管理员重置接口。

### 3.2 商品与库存

- 商品列表是否能正常返回。
- 商品字段是否完整：`id`、`name`、`price`、`stock`、`description`。
- 库存为 0 的商品是否禁止加入购物车。
- 不存在的商品 ID 是否返回合理错误。

### 3.3 购物车

- 正常商品是否能加入购物车。
- 重复加入同一商品时数量和金额是否正确。
- 数量为 0 或负数是否被拒绝。
- 删除购物车商品后数量和金额是否更新。
- 空购物车创建订单是否被拒绝。

### 3.4 订单

- 有商品的购物车能否创建订单。
- 创建订单后购物车是否清空。
- 订单金额是否等于商品小计之和。
- 订单列表是否只展示当前用户订单。
- 订单详情是否能按订单号查询。

### 3.5 状态流转

- 待支付订单是否可以支付。
- 已支付订单是否不能重复支付。
- 已支付订单是否不能取消。
- 待支付订单是否可以取消。
- 已取消订单是否不能支付。

### 3.6 质量风险

- 如果库存为 0 的商品仍可加入购物车，属于库存边界缺陷。
- 如果数量为 0 被当作 1 处理，属于参数校验缺陷。
- 如果已支付订单可取消或重复支付，属于订单状态流转缺陷。
- 如果普通用户可重置数据，属于权限缺陷。

## 4. 本轮测试策略

本轮先做接口自动化验证，重点覆盖：

- 登录鉴权
- 普通用户业务主链路
- 购物车参数校验
- 库存边界
- 订单支付与取消状态流转
- 管理员权限边界

由于被测系统是公共练习站点，本轮只做低并发功能验证，不做高强度压测。测试开始和结束各执行一次管理员重置接口，尽量保证测试数据可控。
