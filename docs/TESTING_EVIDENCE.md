> 最近验证：2026-06-23
> 验证目的：补充“这个平台具体能测什么、测了什么、结果如何”的证据，避免只停留在平台功能介绍。

## 1. 本轮验证对象

本轮使用平台自身作为被测系统，重点验证“接口契约导入 -> 用例生成 -> 接口执行 -> 数据库校验 -> Excel 输出 -> 指标汇总”这条链路。

被测对象包括：

- FastAPI 后端健康接口：`GET http://127.0.0.1:8000/`
- MySQL 连接状态接口：`GET http://127.0.0.1:8000/api/database/status`
- 生成历史查询接口：`GET http://127.0.0.1:8000/api/history?limit=1`
- 接口执行历史查询接口：`GET http://127.0.0.1:8000/api/api-tests/history?limit=5`
- 演示 Swagger / OpenAPI 契约：`docs/demo/openapi.json`
- 演示需求说明：`docs/demo/prd.md`

验证环境：

- 后端地址：`http://127.0.0.1:8000`
- 前端地址：`http://127.0.0.1:5173`
- 数据库：MySQL 已启用并连接成功
- 验证方式：调用平台后端服务、接口执行器、OpenAPI 导入器和 Excel 导出器

## 2. 平台当前能测什么

当前平台已经可以覆盖以下测试内容：

- 接口功能测试：验证接口是否可达、状态码是否符合预期、响应体是否包含关键内容。
- 接口契约测试：基于 Swagger / OpenAPI 自动生成正向、缺参、非法参数、边界、稳定性等接口用例。
- 响应结构测试：支持 JSONPath 断言和 JSON Schema 校验。
- 数据库校验：支持执行只读 `SELECT`，用于验证接口执行后的数据库状态或数据一致性。
- 批量与串联测试：支持接口用例集顺序执行、变量提取和跨接口传递。
- 轻量并发测试：支持重复执行和并发执行，用于观察基础响应时间和稳定性。
- 覆盖率分析：按需求、接口、字段、异常、权限、边界、数据一致性、性能、安全等维度输出覆盖结果。
- 用例质量分析：评估步骤完整性、预期可验证性、测试数据、覆盖标签、自动化就绪度和重复度。
- 报告输出：支持在报告中心汇总执行结果，并导出 Markdown / HTML 报告。
- 测试资源保存：支持将生成结果保存为 Excel，启用 MySQL 后保存生成历史和执行历史。

## 5. 验证过程中发现的问题

第一次执行根接口健康检查时，测试用例仍然沿用了旧的英文响应预期，断言中要求响应体包含 `AI Test Case Generator API`。当前接口实际返回的是中文服务名和 `/docs` 路径，因此第一轮结果出现：

| 指标 | 结果 |
| --- | ---: |
| 执行用例数 | 4 |
| 通过用例数 | 3 |
| 失败用例数 | 1 |
| 断言总数 | 30 |
| 失败断言数 | 2 |

这个结果说明平台执行器能够发现“测试用例预期与实际接口响应不一致”的问题。修正断言预期后，第二轮正式执行结果为 4/4 用例通过、31/31 断言通过。

## 6. 阶段结论

本轮验证证明当前平台不是只能生成测试用例，而是已经可以形成可执行、可量化、可导出的测试链路：

- 可以从 Swagger / OpenAPI 契约自动生成接口测试用例。
- 可以输出覆盖率、自动化就绪比例和用例质量评分。
- 可以实际执行接口测试，并统计通过率、断言结果、响应时间和慢接口。
- 可以执行数据库只读校验，验证数据库连接和查询能力。
- 可以生成 Excel 测试用例文件，便于下载、归档和汇报。
- 可以发现断言预期不匹配这类真实测试问题。

当前验证对象仍以平台自身和 demo 契约为主。接入真实业务系统后，可以沿用同一套指标口径记录接口覆盖率、需求覆盖率、异常覆盖率、缺陷数、失败原因分类和测试结论。
